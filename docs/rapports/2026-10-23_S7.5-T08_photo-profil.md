## 1. Résumé

Chaque compte a maintenant une **photo de profil** :

- **Sans photo** : les **initiales** (prénom + nom) sur une **couleur propre à la personne**, toujours lisible ;
- **« Mon compte »** : « Ajouter une photo », « Changer la photo », « Retirer » ; la photo est réduite dans le
  navigateur, puis **recadrée en carré** de 256 px et **réencodée sans métadonnées** (ni position GPS, ni appareil) ;
- La photo s'affiche dans **l'en-tête** (menu du compte) et dans « Mon compte » ;
- **Visible seulement par toi** (pas de modération nécessaire) ; **effacée avec le compte**.

```
En-tête :  [AN] Bonjour, Awa ▾          Mon compte :  ( photo 72 px )  Awa Ndong
                                                      📷 Changer la photo   🗑 Retirer
                                                      Visible seulement par vous. JPEG, PNG ou WebP.
```

## 3. Décisions techniques

Choix du 2026-10-23 : à ta demande, les **options recommandées** sont retenues sans t'être reposées. Les voici, pour
validation à la lecture de la PR : photo **visible seulement par le titulaire** ; **initiales** par défaut ; **carré de
256 px sans métadonnées** ; JPEG, PNG ou WebP de **5 Mo**, **200 px** au moins ; **effacée avec le compte**.

- **Privée, donc pas de modération** : montrer la photo ailleurs (avis, service client) demandera une autre décision.
- **Aucun identifiant dans l'adresse** : c'est toujours la photo du compte connecté (impossible de voir celle d'un
  autre).
- **Adresse versionnée** (`/compte/photo?v=…`) : une nouvelle photo change l'adresse, l'ancienne n'est jamais montrée.
- **Couleur des initiales** : tirée du nom, parmi 8 couleurs vérifiées (contraste du blanc ≥ 4,5:1, testé).
- **Recadrage dans l'API, pas seulement dans le navigateur** : un envoi direct à l'API est traité pareil.
- Décision complète : [ADR-0055](../architecture/adr/0055-photo-de-profil.md).

## 4. Sécurité

### Relecture indépendante (agent séparé, avant la PR) : 0 haute, 0 moyenne, 1 basse, 4 infos — toutes corrigées

| Problème relevé                                                                                                          | Correction                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| Basse : sans `CLIENT_IP_HEADER`, tous les visiteurs partageaient un seul compteur (un client pouvait bloquer les autres) | Même règle que les autres relais connectés : pas d'adresse sans réglage, la limite par compte s'applique |
| Info : une version périmée dans l'adresse était gardée un an avec une autre photo                                        | Gardée seulement si la version correspond à la photo servie ; sinon revalidée                            |
| Info : photo gardée un an dans le cache d'un poste partagé                                                               | **Une journée** au plus (`private, max-age=86400`)                                                       |
| Info : la copie des données ne contenait pas la photo elle-même                                                          | Photo ajoutée (WebP en base64) ; testé                                                                   |
| Info : réponse de l'API lue en entier avant le contrôle de taille ; erreurs sans `Cache-Control`                         | Lecture arrêtée au-delà de 256 Ko ; erreurs en `no-store` ; testé                                        |

Sans problème selon la relecture : impossible de lire la photo d'un autre (session seule, testé) ; caches privés
(`private`, `Vary`, `ETag`, `nosniff`, pas d'optimiseur d'images) ; envoi et retrait protégés contre les requêtes venues
d'un autre site (contrôle d'origine du site, cookie `SameSite=Lax`) ; déni de service borné (corps lu seulement sur
l'adresse exacte avec un jeton bien formé, 6 envois à la fois dans l'API et 4 dans le site, 10 par minute et par
compte, 40 mégapixels, 15 s, 2 recadrages à la fois, première image seulement) ; SVG, GIF et autres refusés ;
métadonnées retirées (testé) ; réponse relayée revérifiée (WebP, taille, ETag) ; journal sans donnée personnelle ;
effacement complet (photo et version, testé) ; contraintes de la base (taille, empreinte, version).

## 7. Limites connues / dette technique

- **Photo privée** : pas encore montrée dans les avis ni au service client (demanderait une modération).
- **Photos dans PostgreSQL** (comme celles des produits) : à déplacer vers un stockage objet avec elles.
- **Pas de recadrage choisi par l'utilisateur** : centre de l'image.
