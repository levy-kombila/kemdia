## 1. Résumé

Le Sprint 4 est terminé : Kemdia a maintenant de **vrais comptes clients**. On peut s'inscrire avec un code reçu par e-mail,
se connecter, rester connecté 30 jours, choisir un nouveau mot de passe, et se déconnecter partout. Les comptes ont des **rôles**
(client, vendeur, modérateur, administrateur), les actions sensibles laissent une **trace** que la base refuse de modifier, et le
site est protégé contre les attaques venues d'autres sites (CSRF), les scripts injectés (CSP à nonce) et les essais en rafale
(limites par visiteur et par compte).

```
Visiteur ──► Site Next.js ──(clé interne + adresse du visiteur)──► API /api/v1 ──► PostgreSQL
   cookies __Host- HttpOnly         proxy.ts : CSRF, CSP à nonce        identity · audit · catalog
```

Le jalon **v0.4.0** peut être étiqueté (§8).

## 4. Sécurité

Failles de l'ancien projet Django fermées pendant ce sprint ([suivi](../securite/heritage-audit-django.md)) :

| Faille  | En simple                                       | Fermée par        |
| ------- | ----------------------------------------------- | ----------------- |
| HIGH-11 | Vérification de compte contournable             | S4-T02            |
| MED-10  | Pas de verrouillage après des échecs            | S4-T03            |
| CRIT-06 | Élévation vers superutilisateur                 | S4-T06 (côté API) |
| MED-07  | Pas de hiérarchie dans l'équipe                 | S4-T06            |
| HIGH-16 | CSRF                                            | S4-T07            |
| MED-05  | Pas de limitation de débit                      | S4-T07            |
| LOW-03  | Pas de CSP (renforcée : nonce pour les scripts) | S4-T07            |

- Chaque tâche est passée par une **relecture de sécurité indépendante** avant sa PR ; tout ce qu'elle a trouvé a été corrigé
  (dont : rôle modifiable avec un UUID en majuscules au S4-T06, contrôle CSRF qui ne couvrait pas toutes les adresses au S4-T07,
  codes HTTP perdus par le streaming au S4-T08).
- **Aucun secret dans Git** ; aucun `.env` ni réglage Render modifié par le code. Seul réglage ajouté par toi : `CLIENT_IP_HEADER=cf-connecting-ip`
  sur la démo, après vérification (adresse réelle reçue ; fausse adresse refusée par Cloudflare ; second réseau non confirmé).
