## 1. Résumé

La démo publique peut maintenant montrer **le vrai système** : le site lit le catalogue dans **l'API**, qui le lit dans une **vraie base PostgreSQL**.
Tout reste gratuit : site et API sur Render Free, base sur **Neon Free** (permanente, à Francfort comme Render).

Comme Render gratuit n'a pas de « commande avant déploiement », l'API de démo démarre avec un petit programme qui fait, dans l'ordre :

```
node dist/database/start-demo.js        (seulement si APP_ENV=demo, sinon refus)
  1. migrations de la base          → « la base est à jour »
  2. import du catalogue de démo    → « 112 catégories, 50 produits (1 s) »
  3. l'API                          → /api/health : "database":"ok"
  Une étape échoue → l'API ne démarre pas, Render garde l'ancienne version.
```

Le code est prêt et vérifié par la CI. **La mise en ligne demande quelques réglages de ta part** (comptes et secrets, jamais dans Git) :
voir « Comment mettre en ligne » en fin de rapport.

## 3. Décisions techniques

[ADR-0013](../architecture/adr/0013-demo-render-api-neon.md). Les quatre choix que tu as tranchés :

| Question                            | Choix                            | En simple                                                                                               |
| ----------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Quelle base gratuite ?              | **Neon Free**                    | La base Render gratuite **expire au bout de 30 jours** ; Neon est permanente                            |
| Où publier l'image de l'API ?       | **Docker Hub public**            | Comme le site ; elle ne contient rien de secret                                                         |
| Qui lance migrations et import ?    | **Le conteneur, au démarrage**   | Render gratuit n'a pas de commande avant déploiement ; l'adresse de la base reste dans Render seulement |
| Supprimer le mode fichier du site ? | **Non, pas maintenant** (S3-T08) | `pnpm dev` marche encore sans Docker ; l'ADR-0011 est mis à jour                                        |

Autres points décidés en route :

- **Connexion directe à Neon** (pas l'adresse `-pooler`) : les migrations posent un verrou de session que le « pooler » gère mal ; 5 connexions suffisent.
- **L'import est relancé à chaque réveil** : il est sans doublon (identifiants fixes) et ne prend qu'une seconde. Avantage : une base neuve ou vidée se remplit seule.
- **`TRUST_PROXY` reste à 0** sur la démo : Render ne documente pas combien de relais il place devant l'application, et une mauvaise valeur
  permettrait à un visiteur de **choisir** son adresse IP pour contourner la limite. Conséquence acceptée : les appels **directs** à l'API partagent une limite.
- Render gratuit : **pas de réseau privé** entre services. Le site appelle donc l'API par son adresse publique, en HTTPS, avec la clé interne.

## 4. Sécurité

| Mesure                                                                                                                                        | Risque couvert                                         |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `start-demo.js` refuse tout `APP_ENV` autre que `demo` (vérifié en CI avec `staging`) ; l'import aussi, dans l'image                          | Données de démo ou migration « sauvage » en production |
| Adresse de la base et clé interne **uniquement** dans les variables Render ; GitHub ne connaît que les deploy hooks                           | CRIT-02 (fuite d'identifiants)                         |
| Un import en échec n'affiche que le type et le code de l'erreur (ex. `Error ECONNREFUSED`), jamais son message                                | Mot de passe de la base dans les journaux              |
| Réveil de l'API par `/api/health`, **sans** la clé interne                                                                                    | Clé envoyée inutilement                                |
| `/api/health` du site : source du catalogue seulement, ni adresse ni clé                                                                      | Fuite d'information                                    |
| TLS obligatoire vers Neon (`sslmode=require`) ; le guide fait retirer `channel_binding` (non compris par tous les outils), pas le chiffrement | Écoute du trafic vers la base                          |
| Images inchangées côté durcissement : Trivy, non-root, lecture seule                                                                          | Image vulnérable                                       |

Risques restants : l'API de démo est publique (données de démonstration seulement) ; un seul rôle PostgreSQL (deux rôles au S7, déjà prévu).

## 7. Limites connues / dette technique

- **Première visite après une pause : 1 à 2 minutes** (réveil du site, puis de l'API). Si l'API n'est pas prête dans les 60 s, la page d'erreur propose « Réessayer ».
  Garder les services éveillés coûterait plus que les 750 heures gratuites par mois.
- **Écart volontaire à l'ADR-0012** sur la démo seulement : migrations au démarrage, pas avant. Interdit ailleurs par le code.
- `TRUST_PROXY=0` sur la démo (voir §3). À régler au S7 sur notre serveur, où le relais (Caddy) est connu.
- **Mode fichier du site** : gardé pour le développement ; retrait au **S3-T08** (ajouté au planning).
- L'import ne **supprime** pas un produit retiré du fichier de démonstration (il ne fait qu'ajouter ou mettre à jour). Sans effet aujourd'hui.

## Comment mettre en ligne (≈ 20 minutes, une seule fois)

Le détail est dans [demo-gratuite.md](../guides/demo-gratuite.md), étapes 3 à 7. En résumé :

1. **Fusionner cette PR** : la CI publie `levy2025/kemdia-api` sur Docker Hub. Vérifier qu'il est **public** (Docker Hub → `kemdia-api` → Settings).
2. **Neon** : projet `kemdia-demo`, PostgreSQL 18, Francfort ; copier l'adresse **directe** et retirer `&channel_binding=require`.
3. **Render → nouveau service `kemdia-api`** (image `docker.io/levy2025/kemdia-api:latest`, Free, Frankfurt) :
   `APP_ENV=demo`, `PORT=4000`, `DATABASE_URL`, `DATABASE_POOL_MAX=5`, `API_INTERNAL_KEY` ;
   Docker Command `node dist/database/start-demo.js` ; Health Check Path `/api/health` ; Auto-Deploy : No.
4. **Render → service `kemdia`** (le site) : `API_URL=https://kemdia-api.onrender.com`, **la même** `API_INTERNAL_KEY`, `CATALOG_TIMEOUT_MS=60000`.
5. **GitHub → Secrets and variables → Actions** : secret `RENDER_API_DEPLOY_HOOK_URL`, variable `DEMO_API_URL`.
6. _Actions → CI/CD → Run workflow_ sur `main`.

Pour générer la clé (PowerShell, une commande) :

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```
