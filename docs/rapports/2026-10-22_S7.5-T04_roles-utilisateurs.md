## 1. Résumé

L'équipe Kemdia n'a plus deux rôles (modérateur, administrateur) mais **cinq**, et chacun ne voit que ce qui le
concerne :

- **Catalogue** (ex-modérateur) : produits, fiches, boutiques, vérifications ;
- **Logistique** : livraisons et barème ;
- **Finance** : paiements, remboursements, encaissements, factures, codes promo (écrans au S7.5-T05) ;
- **Service client** : retrouver un client et lire ses commandes, sans rien modifier ;
- **Administrateur** : tout, plus le nouvel écran **Utilisateurs**.

L'administrateur gère l'équipe depuis cet écran : il ajoute quelqu'un (recherche d'un compte, puis rôles), retire ses
rôles quand il part, désactive ou réactive un compte. Les sessions sont coupées tout de suite et tout est tracé.

Tous les comptes reçoivent maintenant un **e-mail quand une connexion vient d'un appareil inconnu**, avec un lien
« ce n'est pas moi » qui déconnecte tout et bloque le mot de passe.

```
Équipe › Utilisateurs                               E-mail « Nouvelle connexion »
[e-mail ou téléphone]  [Rechercher]                 Firefox sur Windows, le 22/10 à 11:18
Awa Ndong  ✓ Double authentification                Ce n'est pas vous ? → /securite/pas-moi
 [✓ Catalogue] [+ Logistique] [+ Finance] …          [Ce n'est pas moi : tout déconnecter]
 Retirer ses rôles… · Désactiver le compte…
```

## 3. Décisions techniques

Choix du propriétaire (2026-10-20) : 5 rôles ; départ = « Retirer ses rôles » + « Désactiver le compte » ;
administrateur nommé depuis le serveur seulement ; avis « nouvel appareil » pour tous avec un lien « ce n'est pas moi ».

Choix du 2026-10-22 : ajout par **recherche puis rôles** ; cookie d'appareil **1 an** ; case **« Je confirme »** ;
après la relecture : **pas d'avis seulement à l'inscription**, et **mot de passe bloqué** par « ce n'est pas moi ».

- **Renommage plutôt que nouveau rôle** : `ALTER TYPE … RENAME VALUE 'MODERATOR' TO 'CATALOG'` garde les lignes : les
  modérateurs actuels deviennent Catalogue sans intervention.
- **Règle des rôles partagée** : `hasRole` / `ROLE_IMPLIES` dans le contrat, copie dans le domaine de l'API vérifiée
  par un test ; le site s'en sert pour le menu, l'API reste juge.
- **Identifiants de recherche dans le corps** des requêtes (et des actions serveur), jamais dans une adresse.
- **Identifiant d'appareil tiré au hasard** par le site (32 octets) plutôt qu'une empreinte du navigateur : fiable,
  sans pistage, sans consentement. L'API n'en garde que l'empreinte SHA-256.
- **Lien « ce n'est pas moi »** : jeton de 256 bits, empreinte seulement, usage unique (`DELETE … RETURNING`), 7 jours ;
  page qui n'agit qu'au clic (prévisualisations de liens), `noindex` et sans `Referer`.
- Décision complète : [ADR-0051](../architecture/adr/0051-roles-equipe-utilisateurs.md).

## 4. Sécurité

### Relecture indépendante (agent séparé, avant la PR) : 0 haute, 3 moyennes, 4 basses — toutes corrigées

| Problème relevé                                                                                                                           | Correction                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Moyenne : une connexion **sans** identifiant d'appareil (appel direct à l'API), ou le premier appareil d'un compte, n'envoyait aucun avis | Sans identifiant : appareil inconnu → avis ; seul l'appareil de l'**inscription** est dispensé (ton choix) ; testé                                     |
| Moyenne : 20 connexions avec des appareils inventés effaçaient la ligne du lien « ce n'est pas moi » et inondaient la boîte du titulaire  | Une ligne au lien encore valable n'est **jamais** oubliée ; **5 avis valables au plus** par compte, le reste tracé sans e-mail ; testé (30 connexions) |
| Moyenne : les commandes d'un client lues par le service client n'étaient pas tracées ; compte inconnu → page vide                         | `support.orders_viewed` (avec la référence) à chaque lecture ; `COMPTE_INTROUVABLE` pour un compte inconnu ; testé                                     |
| Basse : un administrateur pouvait changer les rôles d'équipe d'un autre administrateur                                                    | `COMPTE_PROTEGE` (le rôle vendeur, lié à sa boutique, reste possible) ; testé                                                                          |
| Basse : une recherche sans résultat du service client ne laissait pas de trace                                                            | `support.lookup_failed`, sans l'identifiant cherché ; testé                                                                                            |
| Basse : « ce n'est pas moi » laissait le voleur se reconnecter avec le mot de passe                                                       | **Mot de passe bloqué** (ton choix) : nouveau mot de passe par « Mot de passe oublié » ; e-mail et page mis à jour ; testé                             |
| Basse (données personnelles) : appareils absents de la copie des données et gardés sans limite                                            | Ajoutés à la copie (sans empreinte) ; purgés après **un an** sans connexion (ménage horaire)                                                           |
| Info : le rôle Catalogue voit les pièces d'identité des vendeurs                                                                          | Conforme à ton choix du 2026-10-20 (« vérifications » dans Catalogue) ; noté dans l'ADR                                                                |

Trouvé avant la relecture : les appareils connus n'étaient **pas effacés** à la suppression d'un compte (l'effacement
garde la ligne du compte) → supprimés dans l'effacement ; testé.

Sans problème selon la relecture : autorisation fermée par défaut et 2FA sur toutes les routes d'équipe ; aucune
escalade vers administrateur ; « jamais sur soi » insensible à la casse des UUID ; verrous et transactions des
actions ; jeton non devinable et sans fuite (journaux, `Referer`) ; e-mail sans texte venu du navigateur ; actions du
site revérifiées, redirections internes et fixes ; cookie `__Host-`, `HttpOnly`, `SameSite=Lax` ; limites de débit.

## 7. Limites connues / dette technique

- **Finance** : rôle en place dans l'API, écrans au S7.5-T05.
- **Premier jour** : chaque compte existant reçoit un avis à sa première connexion après le déploiement (aucun appareil
  encore connu) — c'est voulu.
- **Mot de passe oublié** : il ne retient pas l'appareil (la connexion suivante peut donner un avis).
- **Lien de l'avis** : sans la variable `PUBLIC_SITE_URL` sur le serveur, l'avis part sans lien.
