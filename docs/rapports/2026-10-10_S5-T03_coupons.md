## 1. Résumé

Kemdia a maintenant des **coupons** : un administrateur crée par exemple « BIENVENUE10 » (-10 %, plafonné) ou « NOEL5000 »
(-5 000 FCFA dès 20 000 FCFA d'articles), avec des dates, un nombre d'utilisations et une limite par compte. Le client tape le
code au moment de commander : la réduction s'applique **aux articles seulement**, jamais deux fois, et le compteur ne peut pas
dépasser sa limite même si deux clients valident en même temps (BR-030). Si la commande est annulée ou pas payée à temps,
l'utilisation est **rendue**.

## 2. Fonctionnalités livrées

| Élément             | Ce que ça fait                                                                                                               | Fichiers principaux                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Règles d'un coupon  | Pourcentage (1 à 90 %, plafond possible) ou montant fixe (avec un minimum d'articles supérieur au montant) ; dates ; limites | `orders/domain/coupon.ts`                         |
| Réduction           | Sur les articles seulement ; pas sur les prix barrés par défaut (BR-031) ; jamais tous les articles ; un coupon par commande | `domain/coupon.ts`, `order.service.ts`            |
| Devis               | `POST /orders/quote` accepte `couponCode` : réduction, total, refus expliqué (`COUPON_*`)                                    | `order.service.ts`                                |
| Commande            | Coupon vérifié et compté dans la transaction de la commande (verrou, compteur +1, utilisation enregistrée)                   | `order.service.ts`, `prisma-coupon.repository.ts` |
| Remise              | Annulation ou paiement non reçu : utilisation rendue ; déclencheur SQL en filet de sécurité                                  | `order.service.ts`, migration                     |
| Administration      | `POST/GET /api/v1/admin/coupons`, `PATCH /api/v1/admin/coupons/{id}` (activer / désactiver), journal d'audit                 | `coupon.service.ts`, `coupon.controller.ts`       |

## 3. Décisions techniques

[ADR-0025](../architecture/adr/0025-coupons.md), avec tes choix du 2026-10-10 :

| Question             | Ton choix                                                                |
| -------------------- | ------------------------------------------------------------------------ |
| Type                 | **Pourcentage ou montant fixe**                                          |
| Assiette             | **Articles seulement** (pas les prix barrés par défaut)                  |
| Limites              | Pas de préférence → **toutes, réglables** (1 fois par compte par défaut) |
| Création             | **Routes d'administration de l'API**                                     |
| Comptage             | **À la commande, rendu si annulée**                                      |
| Coupons par commande | **Un seul**                                                              |
| Code                 | **4 à 20 caractères, sans casse**                                        |

- **Livraison** : frais et livraison offerte calculés sur les articles **après** réduction (un coupon ne sert pas à atteindre la livraison offerte).
- **BR-031** reste une question pour le client : non cumulable par défaut, réglable coupon par coupon.

## 4. Sécurité

- Le client n'envoie qu'un **code** : la réduction est calculée par le serveur avec les prix des variantes verrouillées.
- **Pas de dépassement de limite** : coupon verrouillé dans la transaction de la commande, compteur borné par la base (testé avec deux clients pour la dernière utilisation).
- **Règles figées** : un coupon ne change plus de règles une fois créé (seuls l'activation et le compteur bougent) ; réduction et code de la commande figés ; rien ne s'efface.
- **Administration** : réservée aux administrateurs connectés depuis moins de 15 minutes ; chaque création ou changement au journal d'audit.

**Relecture de sécurité indépendante** (agent séparé, avant la PR) : aucun problème critique ou élevé. Corrigé :

| Gravité | Trouvé                                                                                                                             | Correction                                                                                                        |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Moyen   | Un montant fixe plus grand que les articles donnait une **commande à 0 FCFA** (gratuite à la livraison, impayable en Mobile Money) | Minimum obligatoire et supérieur au montant ; réduction jamais égale aux articles ; la base exige un total > 0    |
| Faible  | Pendant un déploiement, l'ancienne API annulant une commande ne rendait pas le coupon                                              | Déclencheur SQL : toute commande annulée rend son coupon                                                          |
| Faible  | Des codes pouvaient être devinés ; un code « pas encore valable » ou un panier vide révélait son existence                         | Même réponse que « inconnu » ; panier vide : code non regardé ; 10 refus en 15 min → `COUPON_TROP_D_ESSAIS` (429) |
| Faible  | Réglages démesurés (ex. 3 milliards d'utilisations) → erreur 500                                                                   | Bornes dans le contrat et le domaine (400 / 422)                                                                  |
| Info    | Identifiant d'un coupon modifiable par la base ; remplacement de la contrainte des montants en deux temps                          | Identifiant figé ; nouvelle contrainte posée avant le retrait de l'ancienne                                       |

Gardé et noté (ADR-0025) : une commande Mobile Money non payée garde une utilisation 30 minutes (comme le stock, limité par les 3 commandes
ouvertes) ; le lien réduction ⇔ utilisation est garanti par l'application et les tests ; compteurs d'essais en mémoire (Redis au S7).

Aucun secret dans Git ; **aucun `.env` ni réglage Render modifié**.
