## 1. Résumé

Le **blocage du fil principal** de l'accueil (téléphone simulé, 3G, cache vide) est maintenant **stable et bien sous
300 ms**, et la PR **échoue au-delà de 300 ms** (au lieu de 350 ms).

- **Ce qui était en cause** : surtout la **vitesse des serveurs de CI**, qui varie d'un jour à l'autre. Avec le même
  code, l'accueil était mesuré de **82 à 351 ms** sur `main`. Un petit calcul chronométré au début du test
  (« étalon ») le montre : le blocage suit presque exactement la vitesse de la machine.
- **Correction de la mesure** : le ralentissement du processeur est maintenant **étalonné** pour simuler toujours le
  même téléphone ; l'accueil est mesuré sur **5 chargements** au lieu de 3.
- **Allègements réels** (toutes les pages en profitent) : les **photos** ne sont plus des composants à hydrater, et le
  **pied de page** n'est rendu interactif qu'à l'approche. Gain mesuré : **~12 %** du blocage de l'accueil.

```
Accueil, blocage mesuré en CI, code du S8-T04     ×4 fixe (avant)    processeur étalonné (après)
  machine rapide (étalon 18,8 ms)                 157 ms             ~160 ms attendus (×4,26)
  machine lente  (étalon ~33 ms)                  293 ms             112 ms (×2,42)
  machine lente  (étalon ~40 ms)                  358 ms → échec     ~120 ms attendus (×2)
  PR bloquée au-delà de 300 ms (350 ms avant)
```

## 3. Décisions techniques

Choix du 2026-10-24 : à ta demande, les **options recommandées** sont retenues sans t'être reposées. Les voici, pour
validation à la lecture de la PR :

- **corriger la mesure** plutôt que retirer du contenu : processeur étalonné sur une **référence de 20 ms** (la
  vitesse des machines sur lesquelles le budget a été fixé et tenu, S2 à S6), bornes ×2 à ×8 ;
- accueil sur **5 chargements**, **bloquant au-delà de 300 ms** ; les autres pages restent indicatives ;
- photos en **simple `<img>`** (aucune page n'utilisait le flou d'attente ni l'événement de chargement) ;
- **pied de page** rendu interactif à l'approche (avant, ses liens restent de simples liens) ;
- **pas** de zones `<Suspense>` autour du haut de l'accueil, **pas** de rendu en transition : mesurés plus lents ;
- **pas** de changement de contenu (moins de cartes, rangées au défilement) : choix du client et du propriétaire
  (ADR-0042).

Comment les causes ont été trouvées (poste de travail, Chromium sans Playwright, comparaisons A/B **alternées**
entre deux copies du site pour neutraliser la dérive de la machine) :

| Mesure (poste, médianes)                                              | Résultat                                  |
| --------------------------------------------------------------------- | ----------------------------------------- |
| Page vide (React, Next.js, en-tête, pied)                             | ~60 % du blocage de l'accueil             |
| Sans les rangées du bas                                               | −110 ms (déjà différées depuis le S3-T08) |
| Photos en `<img>`                                                     | **−34 ms** (retenu)                       |
| Pied de page rendu à l'approche                                       | **−26 ms** (retenu)                       |
| Zones `<Suspense>` autour de la bannière, rayons, ventes flash        | +40 à +50 ms (écarté)                     |
| Rangées du bas en transition / sans avance de 400 px / sans streaming | +40 ms / 0 / 0 (écartés)                  |

Décision complète : [ADR-0059](../architecture/adr/0059-accueil-300ms-etalonnage.md).

## 7. Limites connues / dette technique

- La correction de l'étalonnage n'est pas parfaitement proportionnelle : une machine lente donne un peu moins de
  blocage (~110 ms) qu'une rapide (~160 ms). Écart acceptable, loin des 300 ms.
- Sur une machine plus de deux fois plus lente que la référence, la borne ×2 est atteinte : la CI le signale ; une
  relance suffit.
- Le gros du blocage restant vient de React et Next.js eux-mêmes (page vide ≈ 60 %) : aller plus bas demanderait de
  changer le contenu de l'accueil (choix du client) ou d'alléger l'en-tête.
- Sans JavaScript, les rangées du bas de l'accueil restent sur leur zone d'attente (contenu présent dans le HTML mais
  placé par un petit script de React) : sans effet sur les moteurs de recherche, qui exécutent le JavaScript.
